# REVIEW.md

Comprehensive code review of the starter implementation in `app/main.py`.

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 33–37) | Ignores IST conversion (uses naive/UTC fields); calculates `minutes = int(diff / 60)` before grace comparison (`minutes > 10`), so 10 min 1 sec (601 s) is truncated to 10 min and deemed on-time; ignores overnight shifts. | Punch-in at `09:40:01` for shift `09:30` returns `0` instead of `10`. An overnight shift punch-in calculates against the wrong calendar day. | Truncate timestamps to whole seconds (R1), compute elapsed seconds from IST `shift_start_dt`, strictly check `diff_sec > 600`, and floor divide elapsed seconds by 60 from shift start. |
| 2 | `compute_work_hours` (lines 40–41) | Uses Python's built-in `round()`, which performs round-half-to-even (banker's rounding) and suffers from floating-point representation inaccuracy. | Working 16182 seconds (4.495 hours) rounds to 4.49 instead of 4.50. | Use `Decimal` division quantized with `ROUND_HALF_UP` to two decimal places (`0.01`). |
| 3 | `compute_overtime` (lines 44–47) | Missing 30-minute qualification threshold (counts any overtime > 0); builds shift end from `date_str`, failing overnight shifts whose shift end is on the following calendar day. | Punch-out 18:35 for shift end 18:30 returns 5 min instead of 0. Overnight shift (22:00–06:00) shift end is set to 06:00 on the starting day. | Reconstruct proper IST shift boundaries (adding 1 day for overnight shifts). Count overtime as `floor(diff / 60)` only when `diff >= 30 * 60`, otherwise 0. |
| 4 | Client setup & timestamps (lines 11–26, 82, 102) | PyMongo `MongoClient` created without `tz_aware=True`; datetimes created with `datetime.now()` or `fromtimestamp()` are naive local server times, causing desynchronization across time zones. | Running on a machine set to UTC, US/Pacific, or DST shifts yields incorrect calendar dates and shift offsets. | Initialize `MongoClient(uri, tz_aware=True)`; always work with timezone-aware UTC instants and explicit IST timezone `timezone(timedelta(hours=5, minutes=30))`. |
| 5 | `create_employee` (lines 78–85) | Check-then-insert race condition (`find_one` then `insert_one`); no input validation on `emp_code`, email format, string lengths, `shift_start != shift_end`, or calendar date validity; `created_at` returned as raw datetime instead of epoch ms. | Two concurrent requests with `EMP0001` both pass the check and race. `joined_on="2026-02-30"` is accepted. `shift_start="09:30"` and `shift_end="09:30"` accepted. | Create unique index on `emp_code`, catch `DuplicateKeyError` and raise 409. Add strict Pydantic model with regexes, date validation, and serialize `created_at` as epoch ms. |
| 6 | `list_employees` (lines 89–96) | Off-by-one pagination bug: `skip = page * page_size` skips page 1 completely (page 1 skips 20 items); `total` counts entire collection ignoring `department` filter; unconstrained page bounds; no sorting. | `GET /employees?page=1&page_size=20` returns records 21–40. With `department=Engineering`, `total` reports total company headcount. | Set `skip = (page - 1) * page_size`. Sort by `emp_code` ascending. Filter count query with `q`. Enforce `page >= 1` and `1 <= page_size <= 100`. |
| 7 | `punch_in` (lines 100–121) | Unknown employee causes `TypeError` → HTTP 500 when accessing `emp["shift_start"]`; check-then-insert race condition; no validation of status (accepts `ABSENT`/`LEAVE`); falsy `punched_at=0` falls back to `datetime.now()`; leaks `id`/`_id`. | `POST /attendance/punch-in` for non-existent employee crashes with 500. `status="VACATION"` accepted. `punched_at=0` accepted as valid timestamp. | Check employee existence and return 404. Restrict status to `{PRESENT, WFH, ON_DUTY}`. Validate `StrictInt` range `[100000000000, 4102444800000]`. Rely on unique index `(emp_code, date)` and catch `DuplicateKeyError` → 409. |
| 8 | `list_attendance` (lines 125–151) | Fetches entire collection into Python memory with `list(db.attendance_logs.find(q))` and sorts in memory; does not sort by secondary key `emp_code`; leaks `_id` as `id`; no `date_from > date_to` check; no pagination bounds. | Requesting attendance on a 100k-record database causes high latency, high memory usage, and potential OOM crash. Query with `date_from=2026-07-10&date_to=2026-07-01` returns empty list instead of 422. | Push filters, sort (`date` desc, `emp_code` asc), skip, and limit down to MongoDB cursor. Check `date_from > date_to` and raise 422. Exclude `_id` and serialize records properly. |
| 9 | `health` (lines 72–74) | Always returns `{"status": "ok"}` with HTTP 200 without checking if MongoDB is reachable. | Stopping the MongoDB instance still causes `GET /health` to return 200 OK. | Execute `db.command("ping")` inside `health()`. Return 200 `{"status": "ok"}` on success, or catch exceptions and return HTTP 503. |
| 10 | Attendance record serialization (lines 118–121, 148–150) | Inconsistent and leaky response formats: includes internal Mongo `id`, returns raw BSON datetimes, does not handle legacy records missing `half_day` or `history`. | Response contains `"id": "60c72b2f..."` and ISO string dates instead of epoch integer milliseconds. | Implement a unified `serialize_record(doc)` helper converting all UTC BSON datetimes (including in `history[].changes`) to epoch ms, omitting `_id`, and defaulting missing legacy fields. |
| 11 | Concurrency & Indexing | No startup index creation in lifespan; no unique compound index on `(emp_code, date)` for attendance logs or `emp_code` for employees. | Concurrent identical punch-ins can produce duplicate records for the same employee and date. | Add FastAPI lifespan context manager that creates all required indexes idempotently on application startup. |

### Things examined and decided were fine:
- **`load_dotenv(override=False)`**: Python-dotenv's default behavior is `override=False`, which ensures real environment variables injected by the system or test runner take precedence over `.env`. We make `override=False` explicit in code.
- **Synchronous PyMongo endpoints under FastAPI**: Defined as standard `def` endpoints (not `async def`), allowing FastAPI to run them in its external threadpool (`anyio.to_thread.run_sync`), preventing blocking of the async event loop under concurrent load.
